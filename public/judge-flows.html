1. From worry to protection

The user journey, without options jargon.

Person already holds SOLThey want upside, but worry about a price drop.

Say: “We start with the holder's goal, then translate it into an option. We do not make them start with Greeks.”

2. What happens in Web3

The website displays. The wallet approves. The program checks.

Pricing modelMaker calculates bid and askPrices use SOL spot, strike, expiry, assumed volatility, and a rule-based spread.
On-chainMaker funds a market and publishes quotesQuote accounts contain side, price, expiry, and remaining size.
Is a usable quote available?No quote means planning only. An estimate cannot become a fake fill.
User signs the exact transactionWallet approval is required before an order is submitted.
Soleil program validates and recordsChecks market, side, size, and expiry; then creates a position account.
Portfolio and Explorer show proofConfirmed state comes from Solana, not a local mock order.

Say: “The quote account is real. Its price is currently generated by our model, not discovered in a competitive order book.”

3. Where Devnet SOL goes

Example: user buys a put. This is test currency, not real money.

Maker funds the marketEach strike, expiry, and call/put market has its own SOL liquidity.
Buyer pays the premiumQuantity “1 SOL” means one SOL of option notional; premium is smaller and shown separately.
Program reserves possible payoutIt consumes quote size and creates the user's position.
At expiry, authorized signer provides SOL priceProgram calculates put value: strike minus expiry price, if positive.
Below strikePut has intrinsic value; program pays SOL if due.
At or above strikeNo intrinsic payout; buyer spent the premium.

Say: “A $110 put with SOL at $90 has $20 intrinsic value per SOL of notional, before the premium and fees.”

The authorized expiry-price signer is a prototype trust dependency. The chart does not guarantee a treasury floor.
